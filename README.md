# 소셜임팩트뉴스 인스타그램 카드뉴스 자동 발행 시스템

매일 오전 11시에 socialimpactnews.net 최신 기사 10건을 수집해 → AI가 카드뉴스 텍스트를 만들고 →
1080×1350 카러셀 이미지를 렌더링한 뒤 → 인스타그램에 자동 발행합니다.

편집자가 가장 오래 붙잡던 **"기사 원문에서 카드별 핵심 메시지 뽑기"** 단계를 자동화하는 것이 목적입니다.
사람은 발행된 게시물을 확인하고 오탈자만 최종 점검합니다.

```
RSS 수집 → 본문 스크래핑 → AI 요약(카드 텍스트) → 계정 매핑 → 카드 이미지 5장 → 인스타그램 발행 → 실행 로그
```

---

## 1. 설치

```bash
python3 -m venv .venv && ./.venv/bin/pip install -r requirements.txt
```

```bash
cp config/settings.example.env config/settings.env
```

`config/settings.env`에 값을 채웁니다. **이 파일에는 토큰이 들어가므로 공유·커밋하지 마세요.**

| 키 | 설명 |
|---|---|
| `ANTHROPIC_API_KEY` | AI 요약용. 비우면 API 없이 도는 추출식 요약(`rule`)으로 자동 전환됩니다. |
| `IG_USER_ID` / `IG_ACCESS_TOKEN` | 인스타그램 프로페셔널 계정의 Graph API 자격증명 |
| `PUBLIC_IMAGE_BASE_URL` | **필수.** 아래 2-1 참고 |
| `ALERT_WEBHOOK_URL` | 실행 실패 시 알림 받을 주소(Slack Incoming Webhook 등). 선택 |

설정 상태는 한 번에 점검할 수 있습니다.

```bash
./.venv/bin/python -m socialcard doctor
```

### 2-1. 이미지 공개 URL이 필요한 이유

Instagram Graph API는 **로컬 파일을 업로드받지 않고 공개 접근 가능한 이미지 URL만** 받습니다.
그래서 렌더링된 PNG는 `out/<run-id>/` 아래 저장되고, `PUBLIC_IMAGE_BASE_URL`과 합쳐져 URL로 전달됩니다.

```
out/run-20260725-110000/SIN6833_01.png
  → https://cdn.example.com/cardnews/run-20260725-110000/SIN6833_01.png
```

`out/` 디렉터리를 S3/Cloudflare R2 같은 정적 호스팅에 동기화하거나, 웹서버로 서빙한 주소를 넣으세요.
(중계형 자동화 도구를 쓴다면 `PUBLISHER=webhook` + `PUBLISH_WEBHOOK_URL`로 페이로드만 넘길 수도 있습니다.)

## 2. 실행

먼저 **드라이런**으로 카드와 캡션만 만들어 눈으로 확인하세요. 발행은 일어나지 않습니다.

```bash
./run.sh --dry-run
```

결과는 `out/<run-id>/` 에 쌓입니다 — 카드 PNG, 기사별 JSON(카드 텍스트·캡션), `report.json`, `run.log`.

실제 발행:

```bash
./scripts/publish.sh
```

**`./run.sh`를 그대로 쓰면 안 됩니다.** 렌더링 직후 곧바로 인스타그램에 이미지 URL을 넘기는데,
그 시점에 새 `run-` 폴더는 아직 정적 호스팅에 올라가 있지 않아 인스타그램이 이미지를 가져오지
못합니다. [publish.sh](scripts/publish.sh)는 순서를 강제합니다.

```
① 렌더링(발행 없음) → ② 이미지 push → ③ 공개 URL이 HTTP 200인지 확인 → ④ 발행 → ⑤ 링크인바이오 push
```

③에서 이미지가 아직 공개되지 않았으면 **발행하지 않고 멈춥니다.** 절반만 올라간 게시물이 생기는
것보다 낫기 때문입니다. `--limit 1` 같은 옵션은 그대로 넘어갑니다.

⑤가 따로 있는 이유는 **링크인바이오가 발행 이력에서 만들어지기 때문**입니다. ④가 끝나야 방금 올린
기사가 목록에 들어가므로, ②의 push만으로는 공개 페이지가 한 실행씩 뒤처집니다.

자주 쓰는 옵션:

```bash
./run.sh --dry-run --limit 3                       # 3건만
./run.sh --source csv --csv latest_articles.csv    # CSV 양식으로 오프라인 테스트
./run.sh --target story                            # 캐러셀 대신 스토리
./run.sh --force                                   # 중복 검사 무시하고 재발행
./.venv/bin/python -m socialcard history           # 실행 이력
```

종료 코드: `0` 성공 / `1` 일부 실패 / `2` 실행 실패(발행 없음).

## 3. 매일 오전 11시 자동 실행

```bash
./scripts/install_schedule.sh install
```

macOS `launchd`에 등록됩니다. 해제는 `uninstall`, 상태는 `status`, 즉시 1회 실행은 `trigger`.

> 11시에 Mac이 꺼져 있거나 절전 상태면 실행되지 않습니다. 매일 확실히 돌려야 한다면
> 상시 켜져 있는 서버나 클라우드 크론에서 `run.sh`를 호출하세요.

## 4. 카드 디자인

발행 대상 계정은 **@soimnews**, 바이라인은 **소셜임팩트뉴스 press@soimnews.net** 입니다.
색상은 소임뉴 로고(`소임뉴2.png`)에서 그대로 뽑아 썼습니다.

| 역할 | 값 | 쓰이는 곳 |
|---|---|---|
| 브랜드 | `#00A76B` | 커버 배경, 라벨 배지, 상단 바 |
| 액센트 | `#89F394` | 구분선, 진행 바, 멘션 |
| 잉크 | `#3C3C3C` | 본문 글자, 아웃트로 배경 |
| 페이퍼 | `#FBFCFB` | 본문 카드 배경 |

기본 5장 카러셀입니다. `BODY_CARD_COUNT`로 본문 장수를 조절할 수 있습니다.

| 장 | 내용 |
|---|---|
| 01 | 커버 — 로고 마크 + 섹션 배지 + 후킹 헤드라인 + 맥락 한 줄 |
| 02~04 | 본문 — 킥커 배지(무슨 일이 / 핵심은 / 왜 중요하냐면) + 핵심 숫자 배지 + 완성된 문장 |
| 05 | 아웃트로 — 로고 + "기사 전문 보기" + 원문에만 있는 내용 + 매체 주소 |

모든 카드 하단에 구분선·바이라인·진행 바가 들어가고, 텍스트 블록은 이 영역을 침범하지 않도록
폰트를 자동으로 줄입니다.

### 왜 정사각형이 아니라 4:5인가

**인스타그램 프로필 격자는 4:5로 잘라 보여줍니다.** 1080×1080으로 만들면 격자에서 좌우가 각각
108px씩 잘려 글자가 사라집니다. 그래서 처음부터 4:5(`1080×1350`)로 렌더링합니다. 피드에서
차지하는 세로 공간도 넓어집니다. 크기는 `CARD_SIZE`(가로)와 `CARD_HEIGHT`(세로)로 바꿀 수 있고,
푸터는 캔버스 바닥 기준으로 붙어 세로가 바뀌어도 위쪽 요소는 그대로 남습니다.

아웃트로 카드에는 프로필 링크 대신 **매체 주소**(`BRAND_SITE`, 기본 `socialimpactnews.net`)를
노출합니다. 인스타그램 게시물 이미지는 클릭되지 않으므로, 프로필 바이오에 기대지 않고 독자가
눈으로 읽고 찾아갈 수 있어야 하기 때문입니다. 이 값을 비우면 예전처럼 프로필 링크를 안내합니다.

### 구문 단위 끊어읽기 줄바꿈

카드뉴스는 한 줄이 곧 한 호흡이라, 줄 끝을 꽉 채우는 일반 줄바꿈은 '충남청년센터가 청년정책 /
플랫폼을' 처럼 의미 덩어리 한가운데를 끊습니다. [typeset.py](socialcard/typeset.py)는 어절을
최소 단위로 두고(단어는 절대 쪼개지 않음) 끊어읽기 자연스러움을 점수로 매겨, 문단 전체 비용이
최소가 되는 줄 나눔을 동적 계획법으로 찾습니다.

```
문장부호 뒤 (11) > 연결어미 뒤 (7) > 두 글자 조사 뒤 (4.5) > 한 글자 조사 뒤 (2.5) > 그 외 (0)
'함께 / 지난 / 이번' 처럼 뒤 어절에 붙어 읽히는 부사·관형사 뒤는 (-6)
```

마지막 줄에 짧은 단어 하나만 남는 고아 줄도 앞줄에서 한 어절을 내려 방지합니다.

## 5. 카드 내용 — 읽고 나서 원문을 누르게 만들기

카드뉴스는 완결된 콘텐츠가 아니라 **기사 전문으로 데려가는 홍보물**입니다.
[summarize.py](socialcard/summarize.py)는 그 목적에 맞춰 다음 규칙으로 텍스트를 만듭니다.

- **한 장에 메시지 하나.** 카드마다 킥커로 역할을 고정합니다 — 무슨 일이 → 핵심은 → 왜 중요하냐면.
- **문장을 중간에 끊지 않습니다.** 잘린 문장은 정보가 아니라 노이즈이므로, 카드에 통째로 들어가는
  문장을 우선 고릅니다(`_fact_score`가 길이 초과분에 감점).
- **구체적 사실을 앞세웁니다.** 숫자·일정·금액·규모가 있는 문장에 가점을 주고, 그중 핵심 값
  (`9월 5일`, `15개`)을 카드 상단 배지로 따로 띄웁니다.
- **읽기 방해가 되는 삽입구를 걷어냅니다.** `제주창조경제혁신센터(대표이사 이병선, 이하 제주센터)가`
  → `제주창조경제혁신센터가`.
- **마지막 카드는 클릭 이유를 만듭니다.** `read_more`에 원문에만 있는 내용을 한 줄로 적습니다.

### 커버 후킹 — 네 유형 중에서 고릅니다

캐러셀은 첫 장이 전체의 대부분을 결정하는데, 언론사 계정은 "당신이 몰랐던 N가지" 같은 주제 은폐형
낚시를 쓸 수 없습니다. 그래서 없는 궁금증을 만드는 대신 **기사에 이미 있는 사실 중 무엇을 커버로
끌어올릴지**를 고르게 했습니다. 모델은 기사 종류에 맞는 유형 하나를 `hook_type`으로 골라 제출하고,
그 값은 기사별 JSON에 함께 저장되어 나중에 어떤 유형이 잘 먹혔는지 확인할 수 있습니다.

| 유형 | 쓰는 기사 | 예 |
|---|---|---|
| `deadline` 마감형 | 모집·공모·신청 | 신청은 이달 31일까지 |
| `scale` 규모형 | 숫자 자체가 뉴스 | 82팀이 지원해 8팀이 남았다 |
| `stake` 이해관계 전환형 | 협약·MOU·제휴 | 충남 청년정책, 전국에서 검색된다 |
| `scene` 장면형 | 인터뷰·기고·현장 | 폐지 1kg에 50원, 시급 1226원 |

### API 없이 쓰는 후킹 (`rule` 폴백)

`ANTHROPIC_API_KEY` 없이도 네 유형 중 **마감형과 규모형은 기계적으로 적용됩니다.** 없는 문구를
지어내지 않고, 기사에 이미 있는 사실을 커버로 끌어올리는 방식입니다.

- **마감형** — 모집·공모 기사에서 신청 마감일을 찾아 헤드라인 끝에 붙입니다.
  `제주센터, 성수동 팝업스토어 참여기업 모집…` → `성수동 팝업스토어 참여기업 모집, 31일까지`
- **기관명 주어 제거** — 지면 제목은 기관을 주어로 세우지만(`헬로우뮤지움, 국제기획전 … 개최`)
  커버에서 먼저 읽혀야 하는 것은 '무엇을'이라 앞머리 기관명을 걷어냅니다. 기관은 본문 카드와
  계정 태그에 그대로 남습니다.
- **잘린 문장 방지** — 커버 부제와 본문 카드 모두 통째로 들어가는 문장을 우선합니다.
  실제 기사 10건에서 말줄임으로 끊긴 카드가 40장 중 12장 → 2장으로 줄었습니다.

이해관계 전환형(협약·MOU 기사를 독자 관점으로 뒤집기)과 장면형은 판단이 필요해 AI 경로에만
있습니다. 이 두 유형이 필요한 기사에서는 폴백 헤드라인이 기사 제목에 가깝게 남습니다.

### 편집자가 손보는 통로 — `config/overrides.csv`

위 한계에 걸리는 몇 건을 편집자가 직접 고치는 곳입니다. 드라이런으로 결과를 본 뒤
현재 문구가 채워진 템플릿을 만들고, 고칠 줄만 손보면 됩니다.

```bash
./.venv/bin/python -m socialcard overrides --from-run <run-id>
```

`config/overrides.csv`가 만들어집니다. **빈 칸은 덮어쓰지 않으므로** 바꿀 칸만 고치면 됩니다.

```
article_id,url,headline,hook,read_more,body_cards,drop_cards,exclude_tags
SIN6833,,충남 청년정책 전국에서 검색된다,충남청년포털과 ‘열고닫기’가 연결된다.,,,3,
```

| 컬럼 | 하는 일 |
|---|---|
| `headline` `hook` | 커버 문구를 덮어씁니다. 커버 카드에도 함께 반영됩니다 |
| `read_more` | 아웃트로의 '원문에 더 있는 것' 한 줄 |
| `body_cards` | **본문 카드를 통째로 다시 씁니다.** 아래 참고 |
| `drop_cards` | 빼버릴 본문 카드 번호(`3` 또는 `3,4`) |
| `exclude_tags` | 이 기사에서만 태그하지 않을 계정(`mysc.official`) |

`headline`·`hook`·`read_more`·`body_cards`에는 **`\n` 두 글자로 줄바꿈을 지정**할 수 있습니다. 자동 조판이
좋은 지점을 찾지만, 커버 문구는 호흡을 직접 정하고 싶을 때가 있습니다.

```
“7년이면 30%는\n쓸 줄 알았어요”
```

지정한 위치는 그대로 지키고 나머지는 기존대로 자동 조판합니다. 커버는 **지정한 줄 수에 맞는
폰트를 찾아 내려갑니다** — 90pt로는 `내가 / 사회적경제를 안다고 / 말할 수 있을까?`처럼 한 줄이
더 접히므로 84pt로 낮춰 두 줄을 맞춥니다. 그 줄 수로 맞출 수 없으면 글자가 잘리지 않도록
원래 한도로 되돌립니다.

**`body_cards`** — `|`로 카드를 나누고, `::` 앞은 킥커입니다(생략하면 기본 킥커가 붙습니다).
기사 소제목을 그대로 카드로 옮기거나, 폴백이 엉뚱한 문장을 골랐을 때 통째로 갈아끼웁니다.
숫자·일정 배지는 본문에서 자동으로 뽑습니다.

```
충남 1위::충청남도 15개 시·군 중 감소율 1위를 기록했다.|어떻게::사고 10건을 자동 감지했다.
```

**`drop_cards`** — 폴백이 비슷한 문장을 두 카드에 연달아 뽑았을 때 한 장을 덜어냅니다. 남은
카드는 번호가 1부터 다시 매겨져 페이지 표기(`03/04`)·진행 바·파일명이 모두 따라갑니다. 커버와
아웃트로는 구조상 뺄 수 없어 번호를 적어도 무시됩니다.

**`exclude_tags`** — 본문에 스쳐 지나간 기관까지 태그돼 알림이 가는 게 어색할 때 씁니다.
`config/accounts.json`의 매핑은 그대로 두므로 **그 기관이 주인공인 다른 기사에서는 정상 태그**됩니다.
계정 자동 등록 뒤 태그를 다시 계산해도 제외가 풀리지 않습니다.

기사 CSV의 컬럼이 아니라 별도 파일로 둔 이유는 **정기 실행이 RSS 수집이기 때문**입니다. 기사 CSV에
컬럼을 두면 오프라인 테스트에서만 쓸 수 있고 매일 도는 실행에는 닿지 않습니다. 이 파일은 `article_id`
또는 `url`로 기사를 찾으므로 수집 방식과 무관하게 반영되고, 덮어쓴 기사는 실행 결과에 표시됩니다.

`--from-run`을 매일 돌려도 이미 있는 줄은 건드리지 않고 새 기사만 뒤에 붙습니다. 등록된 문구는
`overrides` 를 인자 없이 실행해 확인할 수 있습니다.

캡션은 인스타그램이 앞 두 줄만 펼쳐 보이는 점을 감안해 `요약 → 원문 유도 → 링크 → 해시태그` 순으로
조립됩니다.

> **AI 제공자가 품질을 좌우합니다.** `ANTHROPIC_API_KEY`가 있으면 Claude가 위 구조에 맞춰 네 유형
> 전부에서 후킹 헤드라인을 새로 씁니다. 키가 없으면 폴백(`rule`)이 마감형·규모형만 적용하고
> 나머지는 기사 제목에 가깝게 남습니다(위 참고). 이때 실행 결과에 경고가 표시됩니다.

## 6. 기사 전문으로 보내는 경로

인스타그램은 캡션의 URL을 클릭 가능한 링크로 만들지 않고, 공식 Graph API는 스토리 링크 스티커도
지원하지 않습니다(비공식 API로 붙이는 방법이 있으나 계정 정지 위험이 있어 쓰지 않았습니다).
그래서 실제로 동작하는 경로를 이렇게 만듭니다.

```
게시물 → 프로필 바이오 링크 → 링크인바이오 페이지 → 기사 전문
```

[linkinbio.py](socialcard/linkinbio.py)가 발행 이력에서 최근 기사를 읽어 매 실행마다
`out/index.html`을 다시 만듭니다(모바일·다크모드 대응). 저장소 최상위에 두는 이유는 자체 도메인을
붙였을 때 저장소 이름이 경로에서 사라져 페이지가 도메인 루트가 되기 때문입니다. 노출 건수는 `LINKINBIO_LIMIT`
(현재 5)입니다. **새 기사를 발행하면 목록이 자동으로 바뀌므로 프로필 링크는 한 번만 걸어두면 됩니다.**

`LINKINBIO_BASE_URL`에 페이지 주소를 적으면 캡션에도 `오늘의 기사 모음: <주소>`가 함께 들어갑니다.

### 호스팅 — 이미지는 raw, 링크 페이지는 Pages

카드 이미지(PNG)와 링크 페이지(HTML)는 **같은 저장소를 쓰지만 서빙 경로가 다릅니다.**

| 대상 | 주소 | 이유 |
|---|---|---|
| 카드 이미지 | `raw.githubusercontent.com/socialimpactnews/socialimpactnews.github.io/main/…` | PNG는 raw로 정상 서빙됨 |
| 링크 페이지 | `https://socialimpactnews.github.io` | **HTML은 raw로 안 됨** |

저장소 이름을 `<조직명>.github.io`로 두면 Pages가 저장소 루트를 도메인 루트로 서빙해
경로도 개인 아이디도 주소에 남지 않습니다. Pages를 따로 켤 필요도 없습니다.

페이지는 최상위와 **옛 경로 `/linkinbio/` 두 곳에 함께** 생성됩니다. 프로필 바이오에 한 번 나간
주소는 회수할 수 없으므로, 페이지 위치를 옮기더라도 옛 주소가 404가 되면 안 되기 때문입니다.

raw는 HTML을 `content-type: text/plain` + `x-content-type-options: nosniff`로 내보내서, 브라우저가
웹페이지로 렌더링하지 않고 소스를 글자로 보여줍니다. 그래서 링크 페이지만 GitHub Pages로 서빙합니다.
Pages는 저장소 `Settings → Pages → Deploy from a branch → main / (root)`로 켭니다.

> 저장소 최상위에 `index.html`이 없으면 사이트 루트는 404가 납니다. **정상입니다** —
> 필요한 것은 `/linkinbio/` 경로뿐입니다.

## 7. 기업·대표 계정 태그

계정은 **카드 이미지에 글자로 찍지 않습니다.** 업로드 시 Graph API `user_tags`로 기능적으로 태깅되어,
게시물 사진의 "태그된 계정"으로 붙고 상대 계정에 알림이 갑니다. 캐러셀에서는 커버(첫 장)에만 붙여
알림이 중복되지 않게 했고, 상대가 태그를 막아둬 거절되면 태그를 빼고 게시물은 그대로 발행합니다.
캡션에도 @멘션을 남기고 싶으면 `CAPTION_MENTIONS=true`로 켤 수 있습니다(기본 꺼짐).

태그 대상이 정해지는 경로는 셋입니다.

1. `config/accounts.json`에 사람이 등록한 매핑
2. 등록된 이름이 기사 본문에 실제로 등장하는지 직접 스캔 (AI가 목록에서 빠뜨려도 놓치지 않음)
3. 미등록 기관은 실행 중 **웹 검색으로 공식 계정을 조회**해 자동 등록

3번은 안전장치를 겁니다. 근거 URL이 실제 `instagram.com` 프로필이고, 모델이 답한 handle이 그 URL의
handle과 일치하며, 확신도가 `high`일 때만 등록합니다. 하나라도 어긋나면 태그하지 않고 미등록으로 남깁니다.
자동 등록분은 `auto: true`와 `source`가 함께 기록되어 나중에 감사할 수 있고, 같은 이름을 매일 다시
검색하지 않도록 `config/accounts.cache.json`에 결과를 캐시합니다. 실행당 검색 건수는
`ACCOUNT_RESOLVE_BUDGET`(기본 6)으로 제한됩니다.

자기 계정(@soimnews)은 기사 바이라인 때문에 본문에 늘 등장하므로 태그에서 제외합니다.

> **`accounts.json`은 손으로 고치지 마세요.** JSON은 항목 사이 쉼표 하나만 빠져도 파일 전체가
> 무효가 되고, 등록해둔 계정이 **전부** 무시됩니다. 아래 `accounts` 명령으로 추가하면 그럴 일이
> 없습니다. 그래도 깨졌다면 `doctor`가 `결과: 확인 필요`로 잡아내고, 실행 요약에도 경고가 뜹니다.

```bash
./.venv/bin/python -m socialcard accounts
```

```bash
./.venv/bin/python -m socialcard accounts --name 도도한콜라보 --handle dodohan --alias "도도한콜라보㈜"
```

별칭에 공백이 있으면 **반드시 따옴표로 감싸세요.** 그렇지 않으면 인자가 잘려 등록에 실패합니다.

```bash
--alias "사회적협동조합 빠띠"
```

  store.py      SQLite 발행 이력 · 실행 로그
  pipeline.py   전체 흐름과 실패 격리
  linkinbio.py  프로필 바이오에 걸 랜딩 페이지 생성
  cli.py        run / history / seed / accounts / overrides / doctor
scripts/
  setup_instagram.sh  단기 토큰 → 60일 장기 토큰 교환 후 settings.env 기록
  publish.sh          렌더 → 이미지 저장소 push → 공개 URL 확인 → 발행 (순서 강제)

## 11. 알아둘 점

- **계정 태그가 현재 동작하지 않습니다(알려진 버그).** Graph API는 이미지 태그에 좌표(`x`, `y`)를
  요구하는데 [publish.py](socialcard/publish.py)의 `_user_tags_param`이 `username`만 보냅니다.
  `error_subcode 2207063 · "이미지에 사용자 태그 위치 누락"`으로 거절되고, 안전장치가 태그를 뺀 채
  게시물만 발행합니다. 태그가 필요하면 인스타그램 앱에서 직접 붙이세요.
- **게시물 수정·삭제는 API로 안 됩니다.** Graph API는 게시만 제공합니다. 내용을 고치려면 앱에서
  삭제한 뒤 발행 이력(`state/socialcard.sqlite3`의 `published`)에서 지우고 다시 발행해야 합니다.
- **AI가 쓴 문장은 사람이 확인해야 합니다.** 발행 후 계정에서 오탈자와 사실관계를 확인하세요.
- 매체 HTML 구조가 바뀌면 본문 추출이 실패합니다. 이때는 수집 단계에서 오류를 내고 발행하지 않습니다.
- Graph API는 캐러셀 최대 10장, 계정당 24시간 25건 발행 제한이 있습니다. 하루 10건은 여유가 있습니다.
- 액세스 토큰은 만료됩니다(장기 토큰 약 60일). 만료되면 발행 단계에서 실패하고 알림이 나갑니다.
